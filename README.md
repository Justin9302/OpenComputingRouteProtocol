# OpenComputingRouteProtocol
This is a Protocol for Distributed AI Computing Router.
> 一个开源、中立、安全的分布式算力路由协议。
> 让算力像互联网一样自由流动，让数据主权回归企业，让计算与绿色能源协同。

## 🌱 项目愿景
在 AI 算力需求爆炸与能源转型瓶颈交织的时代，集中式云算力正面临**电力墙、安全墙、信任墙**的三重约束。
**Open Compute Router (OCR)** 旨在定义一套轻量级、可演进的分布式算力路由协议：
- **中立**：不绑定任何芯片厂商、云厂商或 AI 框架。
- **安全**：基于零信任架构 + IT/OT 分层（IEC 62443），协议**永不直接控制物理电力设备**，控制流单向。
- **市场撮合**：需求侧意图（intent）× 供给侧能力（capability）双边撮合，容量锁定防超卖，任务绑定是**交易结果而非行政指派**。
- **算电协同**：将计算任务与电力价格、绿电供给动态匹配，实现"算力跟着电力走"；撮合成功后单向推送净负荷预测，让机房储能从反应式兜底变为前瞻式调度。
- **时效分级**：从 1 分钟实时底座到 24 小时离线批处理，用时间换取成本与能源的最优解。
- **设备级自治**：电力/算力数据在 Hub/Switch/Router 设备层处理，设备独立维护资源表（类似路由表），资源表对外广播为能力曲线（RFC-007），安全性内生于架构。
## 🏗️ 三层架构
```text
[用户层 / AI Agent]
       │  绑定 MCP，声明算力意图（显存、延迟、成本、安全、时效）
       ▼
[Hub 层 / 控制平面]
       │  验证身份，解析意图，撮合匹配（intent × capability），绑定任务，
       │  单向推送净负荷预测（RFC-009）——信息流双向，控制流单向
       ▼
[Server 层 / 执行平面]
       │  执行计算任务，上报能力曲线（RFC-007），上报状态，本地对接电网开放数据
       ▼
[算力与电力资源池]  (GPU/NPU/微电网/储能)
```
> 🛡️ **安全边界**：OCRP 运行在机房"管理平面"（IT 侧）；PCS/储能控制（OT 侧）由机房 EMS 自己执行，两者之间 zone 隔离（IEC 62443）+ 白名单适配器（fail-closed）。协议的任何消息都不携带设备控制指令。
## 📈 市场模型（撮合闭环）
```text
① 机房上报能力曲线（时段×容量×价格下限×绿电×签约占用）  ← RFC-007
② 用户意图入池（容量/时延/预算/绿电偏好/Tier）           ← RFC-002
③ Hub 撮合：intent × capability，多维权重排序，防超卖锁定  ← RFC-008
④ 绑定（committed）→ 单向推送净负荷预测给机房 EMS        ← RFC-009
⑤ 执行 → 结算 → 释放容量 → 回到 ①                      ← RFC-006/011
```
- 权重合成：`总成本 = 电价(时段)×电量 + 迁移成本 + 时延惩罚 − 绿电加成 − 信任加成`（Tier 作 QoS 过滤：T0-T2 用确定性容量，T3-T10 用弹性容量）
- **防超卖**：撮合成功先 reserve（TTL 锁定），确认后 committed 永久锁定，任何新撮合不得触碰
- **无达标窗口 → PENDING**（"等电来"）：预算低于当日可实现成本时任务挂起，对齐预算约束示例
## ⏱️ 时效分级调度（SLA Tiering）
| **Tier** | **时间窗口** | **典型场景**           | **价格趋势**  | **承诺等级** |
| -------------- | ------------------ | ---------------------------- | ------------------- | ---------- |
| **T0**   | **实时底座** | **工业控制、安全拦截** | **极高**      | 硬承诺 |
| **T1**   | **1 分钟**   | **实时推理、语音交互** | **高**        | 硬承诺 |
| **T2**   | **5 分钟**   | **交互式 Agent**       | **较高**      | 硬承诺 |
| **T3**   | **10 分钟**  | **轻量批处理**         | **中高**      | 软计划 |
| **T4**   | **30 分钟**  | **知识库更新**         | **中**        | 软计划 |
| **T5**   | **1 小时**   | **日报表生成**         | **中低**      | 软计划 |
| **T6**   | **2 小时**   | **模型微调**           | **低**        | 软计划 |
| **T7**   | **4 小时**   | **数据预处理**         | **较低**      | 软计划 |
| **T8**   | **8 小时**   | **大规模训练**         | **极低**      | 软计划 |
| **T9**   | **16 小时**  | **超大规模离线任务**   | **接近免费**  | 软计划 |
| **T10**  | **24 小时**  | **归档、冷数据挖掘**   | **免费/补贴** | 软计划 |
> 承诺等级含义：T0-T2 硬承诺任务取消需付费（机房据此做确定性储能准备）；T3-T10 软计划可随时调整（机房只做计划性准备）。预测推送（RFC-009）的置信度与此挂钩。

## 🚀 快速开始
运行Hub模拟器
```
cd examples
python hub-simulator.py --config mock-config.yaml
```
运行资源表模拟器（RFC-005 设备级自治）
```
cd examples
python resource-table-mock.py
```
运行 30 秒 Demo（提交任务→撮合→负电价时段执行→展示省钱）
```
cd examples
python demo-30s.py
```
模拟算力节点上线（供给侧"在线证据"）
```
cd examples
python server-node-mock.py
```
提交一个MCP算力意图
```
curl -X POST http://localhost:8080/v1/tasks \
  -H "Content-Type: application/json" \
  -d @examples/mcp-intent-example.json
```
> 🔨 **撮合闭环 mock（RFC-007/008）开发中**：`capability-report-mock.py` + `matching-engine-mock.py` 将把能力上报与撮合出清跑成可演示实现（真实 AEMO 电价对拍）。

**我们遵循** "协议先行，代码渐进" 的原则。欢迎通过以下方式参与：
1. **提出 RFC 提案** ：在 `docs/` 下新建 RFC 文档，提交 PR。
