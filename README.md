# OpenComputingRouteProtocol

This is a Protocol for Distributed AI Computing Router.

> 一个开源、中立、安全的分布式算力路由协议。
> 让算力像互联网一样自由流动，让数据主权回归企业，让计算与绿色能源协同。

## 🌱 项目愿景

在 AI 算力需求爆炸与能源转型瓶颈交织的时代，集中式云算力正面临**电力墙、安全墙、信任墙**的三重约束。

**Open Compute Router (OCR)** 旨在定义一套轻量级、可演进的分布式算力电力协同路由协议：

- **中立**：不绑定任何芯片厂商、云厂商或 AI 框架。
- **安全**：基于零信任架构，支持私有算力隔离与端到端加密。
- **算电协同**：将计算任务与电力价格、绿电供给动态匹配，实现"算力跟着电力走"。
- **时效分级**：从 1 分钟实时底座到 24 小时离线批处理，用时间换取成本与能源的最优解。
- **设备级自治**：电力/算力数据在 Hub/Switch/Router 设备层处理，设备独立维护资源表（类似路由表），不受任何第三方影响，安全性内生于架构。

## 🏗️ 三层架构

```text
[用户层 / AI Agent]
       │  绑定 MCP，声明算力意图（显存、延迟、成本、安全、时效）
       ▼
[Hub 层 / 控制平面]
       │  验证身份，解析意图，匹配能源策略，下发调度指令
       ▼
[Server 层 / 执行平面]
       │  执行计算任务，上报状态，本地对接电网开放数据
       ▼
[算力与电力资源池]  (GPU/NPU/微电网/储能)
```


## ⏱️ 时效分级调度（SLA Tiering）

| **Tier** | **时间窗口** | **典型场景**           | **价格趋势**  |
| -------------- | ------------------ | ---------------------------- | ------------------- |
| **T0**   | **实时底座** | **工业控制、安全拦截** | **极高**      |
| **T1**   | **1 分钟**   | **实时推理、语音交互** | **高**        |
| **T2**   | **5 分钟**   | **交互式 Agent**       | **较高**      |
| **T3**   | **10 分钟**  | **轻量批处理**         | **中高**      |
| **T4**   | **30 分钟**  | **知识库更新**         | **中**        |
| **T5**   | **1 小时**   | **日报表生成**         | **中低**      |
| **T6**   | **2 小时**   | **模型微调**           | **低**        |
| **T7**   | **4 小时**   | **数据预处理**         | **较低**      |
| **T8**   | **8 小时**   | **大规模训练**         | **极低**      |
| **T9**   | **16 小时**  | **超大规模离线任务**   | **接近免费**  |
| **T10**  | **24 小时**  | **归档、冷数据挖掘**   | **免费/补贴** |

## 🚀 快速开始

运行Hub模拟器

```
cd examples
python hub-simulator.py --config mock-config.yaml
```

运行资源表模拟器（RFC-005 设备级自治）

```
cd examples
python resource-table-mock.py
```

运行 30 秒 Demo（提交任务→调度→负电价时段执行→展示省钱）

```
cd examples
python demo-30s.py
```

#### 🧭 Demo 调度模式（`demo-30s.py`）

调度器对齐 RFC-002 §4.4 预算约束调度，支持三种优化模式（默认 `min_cost`）：

| 模式 | 语义 | 行为示例 |
|---|---|---|
| `min_cost` | 任务总成本最低（可为负） | 真实 2026-01-24 NSW1：11:00–12:55，均价 -9.6 AUD/MWh，2h 成本 -0.54 AUD |
| `max_green` | 绿电比例最高，可牺牲成本 | mock 数据：绿电 95% 窗口（成本 +2.05 AUD） |
| `fastest` | 最早满足预算的窗口，不优化电费 | 真实数据：00:00–01:55，成本 +3.26 AUD |

- **预算约束与 PENDING**：任务总预算（默认 5.0 AUD）低于当日最低可实现成本时无达标窗口，任务保持 PENDING（"等电来"）。例：2026-01-24 当日最低 2h 成本约 -0.54 AUD，预算设 -1.0 AUD 即触发。
- **数据粒度自适应**：按行数识别——288 行 = NEM 5 分钟（2021-10-01 起实际结算粒度），48 行 = 30 分钟（旧 mock 兼容）。
- **诚实约定**：真实数据无绿电比例字段时 `green_ratio` 留空，demo 显示 `n/a` 不编造；`max_green` 在无绿电数据时自动退化为 `min_cost` 并提示。数据文件（`aemo_nsw1_YYYYMMDD.csv`）多个共存时按修改时间加载最新；真实文件建议在 `DATA_SOURCES.md` 记录来源与下载日期。

模拟算力节点上线（供给侧"在线证据"）

```
cd examples
python server-node-mock.py
```

提交一个MCP算力意图

```
curl -X POST http://localhost:8080/v1/tasks \
  -H "Content-Type: application/json" \
  -d @examples/mcp-intent-example.json
```



### 🤝 参与贡献

**我们遵循** "协议先行，代码渐进" 的原则。欢迎通过以下方式参与：

1. **提出 RFC 提案** ：在 `docs/` 下新建 RFC 文档，提交 PR。
2. **完善协议规范** ：修订 `spec/` 下的 JSON Schema 或 YAML 定义。

4. **接入真实电网数据** ：如澳洲 AEMO、欧洲 ENTSO-E、北美 PJM。
