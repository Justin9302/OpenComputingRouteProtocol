## 二、图例与核心不变式

| 元素 | 含义 |
|------|------|
| 信息流双向 | 意图、能力、状态在用户/控制平面/执行平面之间双向交换 |
| 控制流单向 | 控制平面只下发调度信息，不携带任何设备控制指令 |
| 安全边界 | 控制平面（IT 侧）与 OT 侧（PCS/储能）之间 zone 隔离 |

**四条核心不变式（红线，任何修改不得破坏）：**

1. **永不直接控制 OT 侧**：OCRP 是调度协议，不是控制协议——PCS/储能控制永远由机房 EMS 执行。
2. **控制流单向**：协议消息不携带设备控制指令，指令永远不向下穿透安全边界。
3. **设备级自治**：每台设备独立维护资源表（类似路由表），不存在单一中央控制点。
4. **撮合是控制平面职责，不是某一台设备的专属功能**：Hub 做园区级本地撮合，Router 做跨域撮合，Server 承载全局出清与深度管理——职责按规模分布，逻辑一致。

## 三、治理规则

1. **变更即映射**：任何新 RFC、功能新增或实现变更，必须在框架图上找到对应位置（哪个层、哪个形态、哪条流）。
2. **图优先**：当 RFC 文本与框架图冲突时，以框架图为准——它是方向裁判。
3. **先改图，后合入**：若变更需要修改框架图本身，必须先修订本图（经项目维护者确认）才能合入对应变更。
4. **红线不可改**：四条核心不变式任何一条都不允许通过 RFC 修改绕过。
