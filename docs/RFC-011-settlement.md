# RFC-011: 结算与经济模型 (Settlement & Economic Model)

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-10-09
- **最后更新**: 2026-10-09
- **依赖**: RFC-008（撮合）、RFC-010（信任/质押）

## 1. 动机与目标

撮合闭环的商业化基础：谁付钱、付给谁、按什么规则算。本 RFC 定义 settlement record 结构、三种商业模式、负电价结算规则与分账模型。

## 2. SettlementRecord（结算记录）

每笔 committed 任务生成一条，撮合时创建、执行完成时结算：

```json
{
  "type": "settlement_record",
  "settlement_id": "st-20261009-001",
  "task_id": "t-20261009-003",
  "router_id": "nsw1-rack-a",
  "slot_start": "2026-10-09T11:00:00+11:00",
  "slot_end": "2026-10-09T11:30:00+11:00",
  "energy_kwh": 125,
  "settlement_price_aud_per_mwh": -9.6,
  "power_cost_aud": -1.20,
  "green_credit_aud": 0.0,
  "fees_aud": 0.06,
  "parties": ["user-a", "hub-nsw", "nsw1-rack-a"],
  "status": "settled"
}
```

## 3. 三种商业模式

| 模式 | 机制 | 适用阶段 |
|---|---|---|
| **免费聚合** | OCRP 不收费，仅做撮合+预测，靠用户增长与机房采纳获取数据/生态 | 冷启动（当前） |
| **预测即服务** | 机房为 ForecastReport（RFC-009）付费（按预测覆盖量/准确度订阅） | 有预测价值的成熟机房 |
| **撮合分成** | 对撮合成交的电费节省/收益按比例抽成（如 5%），三方分账 | 市场流动性建立后 |

## 4. 分账模型（撮合分成模式）

```
收益 = 结算电价 × 电量（负电价时为负，即"收益"为负 = 双方共同受益于成本为负）
分账 = 收益 × 抽成率（默认 5%，可协商）
参与方：用户（算力成本降低）、机房（消纳+容量利用率）、Hub（撮合服务）
```

## 5. 负电价结算规则（对齐 demo：2026-01-24 NSW1 均价 -9.6 AUD/MWh）

- 当 `settlement_price < 0`：用户以负价结算（执行任务反而获得电费补偿），机房获得消纳（绿电配额/负价套利），Hub 按撮合成交量计费（或免费，冷启动期）。
- **成本为负时"收益"按绝对值分账**：负电价是三方共同的"成本减少"——用户少付、机房多消纳、Hub 抽成基数仍为价格差。
- 下限保护：结算价下限 = max(市场价, 机房 price_floor)（RFC-007），机房不能亏现金成本。

## 6. 结算流程（与 RFC-006 生命周期衔接）

```
执行完成 → 生成结算单 → 对账（实际电量 vs 预测）→ 信任分更新（RFC-010）
→ 分账（按模式）→ 质押释放/违约金扣除 → settlement_status = settled
```

## 7. 安全与合规

- 结算单签名（HMAC），防篡改；争议挂起由 RFC-010 仲裁。
- 定价透明：settlement record 全字段对参与方可见（可审计）。
- 合规边界：本协议不做金融担保、不做现货套利承诺，仅记录撮合结果与结算账目（结算执行依赖外部支付通道，本 RFC 只定义账目格式）。

## 8. 与现有 RFC 的关系

- **RFC-004**：电价信号（AEMO 等）是结算价的来源。
- **RFC-008**：撮合时的预算约束（intent.budget）与结算价必须对账（预算 ≤ 结算价 × 电量 + 费用）。
- **RFC-010**：结算违约 → 信任扣分；质押在结算中托管与释放。

## 9. 未来工作

- 绿电信用（green_credit）与绿证/PPA 的对账接口（对齐 VER/PAC 格式）。
- 跨币种/跨市场结算（AUD 现货 + 其他市场电价的汇率处理）。
- 结算的自动化执行（链上结算/智能合约的可行性评估）。
