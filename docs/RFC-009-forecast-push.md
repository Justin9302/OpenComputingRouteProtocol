# RFC-009: 净负荷预测单向推送 (Forecast Push)

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-10-09
- **最后更新**: 2026-10-09
- **依赖**: RFC-008（撮合出清）、RFC-002（时效分级/置信度）、RFC-003（安全边界）

## 1. 动机与目标

撮合闭环后，机房需要知道"接下来会发生什么"才能做**前瞻式储能调度**（MPC）：预充储能、优化 PCS 充放电、安排柴发启动。当前协议只定义了任务执行（RFC-006），没有定义"净负荷预测"如何标准化下发给机房。

本 RFC 定义：**撮合成功后，Hub 把净负荷预测单向推送给机房 EMS**——让物理层从"反应式兜底"变成"前瞻式调度"。

## 2. 核心原则：单向信息流，无反向控制通道

- **下行只有预测信息，绝无控制指令**：Hub → 机房 EMS 的通道上不允许出现任何"执行/开关/功率设定"类指令。
- 控制权完全留在机房 EMS 内（IEC 62443 zone 分离）：OCRP 提供情报（intel），机房执行（control）。
- 安全模型：信息流双向（RFC-007 上行遥测 + 本协议下行预测）、**控制流单向（永远不进入 OT 控制域）**。

## 3. 消息格式：ForecastReport（Hub → 机房）

```json
{
  "type": "forecast_report",
  "hub_id": "hub-nsw",
  "forecast_id": "fc-20261009-001",
  "generated_at": "2026-10-09T10:50:00+11:00",
  "horizon_h": 24,
  "granularity_min": 30,
  "slots": [
    {
      "start": "2026-10-09T11:00:00+11:00",
      "end": "2026-10-09T11:30:00+11:00",
      "expected_kw": 450,
      "hard_kw": 250,
      "confidence": "hard",
      "source_tiers": ["T0", "T1"],
      "task_ids": ["t-20261009-003"]
    }
  ]
}
```

## 4. 字段说明

| 字段 | 定义 |
|---|---|
| `expected_kw` | 该时段预测净负荷（已撮合任务的功率之和 + 基线） |
| `hard_kw` | 硬承诺部分（T0-T2 已确认任务） |
| `confidence` | `hard`（T0-T2，任务已锁定）或 `soft`（T3-T10，计划可能变更） |
| `source_tiers` | 构成该时段的 Tier 集合（供机房判断可预见性） |
| `task_ids` | 构成该时段的已绑定任务（可审计） |

**置信度分级（对齐 RFC-002 增补）**：`hard` = 任务已确认、变更需付费；`soft` = 计划性任务、可随时调整。机房对 `hard` 段做确定性储能准备，对 `soft` 段只做计划性准备。

## 5. 更新规则

- **事件驱动增量**：任何 committed/release 变化（RFC-006）触发增量推送；无变化不推送（省机房侧处理负载）。
- **周期快照**：每 15 分钟全量（与 RFC-007 对账节奏一致）。
- **漂移报告（可选）**：实际执行与预测偏差超阈值时，机房可回传 `deviation_report`（上行，仅遥测），供 Hub 校准后续预测——**注意：这是遥测不是指令**，仍符合单向控制原则。

## 6. 机房侧消费（参考，非本协议强制）

- 机房 EMS 将 ForecastReport 作为 MPC 输入：预充储能、优化 PCS 充放电计划、柴发启动窗口。
- `hard_kw` 段用于容量预留，`soft` 段用于削峰填谷机会窗口（负电价段吸收、峰段放电）。

## 7. 安全

- 预测推送带 HMAC 签名（RFC-003 身份体系），防注入伪造预测。
- 机房侧接收适配器：只解析 ForecastReport 消息类型，**丢弃/拒绝任何非白名单指令类型**（fail-closed）。
- 本协议消息不携带任何密码、令牌或设备控制参数。

## 8. 与行业标准的对齐

| OCRP 组件 | 行业对应 |
|---|---|
| 单向报告方向 | OpenADR 报告（VTN→VEN 报告） |
| 预测结构 | OCP POM 功率编排 · IEC 61850 负荷预测数据结构 |
| 只读适配器 | IEC 62443 zone 防火墙 + 白名单消息解析 |

## 9. 与现有 RFC 的关系

- **RFC-002 增补**：置信度（hard/soft）与 Tier 挂钩，本协议是置信度的消费端。
- **RFC-006**：本协议的推送时机 = RFC-006 生命周期中 committed→执行之间。
- **RFC-003 增补**：本协议是"信息流双向、控制流单向"原则的具体实现。

## 10. 未来工作

- 预测置信区间（不只 hard/soft 二值，给 ±% 区间）供机房做鲁棒 MPC。
- 偏差反馈闭环：deviation_report 累积后反哺 RFC-010 信任分（预测准确度维度）。
