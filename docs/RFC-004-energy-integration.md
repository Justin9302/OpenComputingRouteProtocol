# RFC-004: 算电协同与电网数据接入

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-08-07
- **最后更新**: 2026-08-07

## 1. 摘要

本 RFC 定义 Open Compute Router 协议的**算电协同（Compute-Energy Co-location）模型**与**电网开放数据接入**机制。通过将计算任务与电力价格、绿电供给动态匹配，实现"算力跟着电力走"，让可延迟任务作为"可转移负荷"参与电网调峰。

## 2. 设计动机

- **电力峰值错配**：AI 算力需求与电网负荷高峰重叠，导致电价飙升与绿电浪费并存。
- **绿电消纳**：夜间风电/光伏过剩时，算力可低成本消纳绿电。
- **需求侧响应**：可延迟任务作为虚拟负荷池，参与电网调峰并获取补贴。

## 3. 电网数据接入

### 3.1 插件化架构

Hub 通过**能源插件**（Energy Plugin）对接不同电网开放数据源，插件实现统一接口（见 [spec/energy-plugin.interface.yaml](../spec/energy-plugin.interface.yaml)）。

```text
[电网开放数据]  AEMO / PJM / ENTSO-E / 中国电力交易中心 ...
       │  实现 Energy Plugin 接口
       ▼
[Hub 能源策略引擎]
       │  价格预测 / 绿电比例 / 需求响应事件
       ▼
[调度决策]  结合 SLA Tier 决定执行时机
```

### 3.2 标准适配器

| 适配器 | 市场 | 用途 |
|--------|------|------|
| AEMO | 澳洲 NEM | 电价预测、负电价、区域节点价格 |
| PJM | 北美 | 实时/日前电价、需求响应 |
| ENTSO-E | 欧洲 | 跨区电价、绿电比例 |

### 3.3 核心数据

- **电价数据（price_data）**：区域节点价格与预测窗口（含负电价）。
- **绿电比例（green_ratio）**：区域可再生发电占比（0~1）。
- **需求响应事件（demand_response）**：调峰补贴与负荷削减目标。

## 4. 算电协同调度逻辑

### 4.1 价格驱动调度

Hub 定期拉取电价预测。若预测未来 N 小时内电价低于 `price_ceiling` 且绿电比例达标，则提前唤醒对应 Tier 的任务执行。

### 4.2 绿电套利

```text
T8/T9/T10 任务 → 仅在绿电过剩/负电价时段执行 → 近似零成本算力
T6/T7 任务   → 优先绿电充裕时段（如夜间风电高峰）
T0-T2 任务   → 实时执行，可依赖本地储能兜底
```

### 4.3 需求响应参与

当电网发布需求响应事件（削峰）时，Hub 可将 `interruptible: true` 的低优任务暂停，作为虚拟负荷池参与响应并获取补贴。

## 5. 与 SLA Tiering 的关系

| 场景 | 协同策略 |
|------|---------|
| 高优任务（T0-T2） | 实时执行，容忍峰值电价，本地储能兜底 |
| 中优任务（T3-T7） | 避开尖峰，等待电价回落 |
| 低优任务（T8-T10） | 仅在绿电过剩/负电价时执行 |

## 6. 安全约束

- 电网数据接入遵循 RFC-003 安全模型，插件与 Hub 之间使用 mTLS。
- 调度决策基于公开市场数据，不涉及企业私有数据。
- 需求响应参与遵循最小权限原则，仅对 `interruptible: true` 任务生效。
