# RFC-010: 信任与信誉机制 (Trust & Reputation)

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-10-09
- **最后更新**: 2026-10-09
- **依赖**: RFC-003（零信任）、RFC-008（撮合权重）、RFC-009（预测推送）、RFC-011（结算）

## 1. 动机与目标

开放环境下，单向预测和信息上报存在**信息可信性问题**：机房可能谎报能力（为占撮合池）、用户可能谎报 intent（为占低价窗口）、预测偏差无追责。本 RFC 定义信任分、质押与惩罚机制，把"信息可信"变成可度量、可惩罚的市场属性。

## 2. trust_score 构成（100 分制）

| 维度 | 权重 | 说明 |
|---|---|---|
| 履约率 | 50 | 已确认任务按时按量执行的比例（RFC-006 执行结果） |
| 预测准确度 | 30 | ForecastReport（RFC-009）偏差统计：\|实际 - 预测\| / 预测 ≤ 阈值才算准 |
| 结算准时率 | 20 | 结算款项/绿电信用按时到账（RFC-011） |

评分更新：每次结算后按事件更新（事件溯源，可审计）。

## 3. 机制

### 3.1 质押（Stake）

- 开放环境首次入场：机房/用户需质押（代币或法币托管），违约从质押扣。
- 质押量 ∝ 申报容量规模（申报越大、质押越高，防"空手套"）。

### 3.2 惩罚（Penalty）

| 违约类型 | 后果 |
|---|---|
| 机房接受撮合后不执行（committed 后拒单） | 扣履约分 + 质押罚款 + 降级（限制可接 Tier 上限） |
| 能力上报虚报（承诺 hard_kw 兑现率低于阈值） | 扣预测准确分 + 降低 trust_factor（撮合排序惩罚） |
| 用户确认后取消 hard 任务 | 扣履约分 + 取消违约金（进结算，RFC-011） |
| 结算拖欠 | 扣结算准时率 + 冻结后续撮合资格 |

### 3.3 信誉入撮合

- RFC-008 §3：`trust_factor = trust_score / 100`，作为排序得分的加成项（同成本取 trust 高者）。
- **Tier 权限绑定**：trust_score < 60 的主体只能接/发 T3-T10 软任务；≥ 80 才可接 T0-T2 硬任务（硬承诺需要信誉背书）。

## 4. 数据与可审计性

- 信任记录：事件溯源（append-only），每个 trust event 带签名（RFC-003 身份体系）。
- 隐私：trust_score 公开（聚合值），原始事件仅争议仲裁时可见。
- 争议仲裁：双向违约争议提交 Hub 仲裁（挂起结算，仲裁后按结果释放或追缴）。

## 5. 与现有 RFC 的关系

- **RFC-003**：信任机制运行在零信任身份体系之上（身份 → 信用账户）。
- **RFC-008**：trust_factor 是撮合权重组成部分（P2 启用）。
- **RFC-011**：结算违约触发信任扣分；质押在结算中托管。

## 6. 未来工作

- 跨 Hub 信用互通（A Hub 的信誉分能否被 B Hub 接受——对齐电力市场信用评级互认）。
- 声誉分迁移（Router 更换设备/机房主体的历史信誉继承规则）。
