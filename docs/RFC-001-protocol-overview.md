# RFC-001: 协议总览与三层架构

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-08-07
- **最后更新**: 2026-08-07

## 1. 摘要

本 RFC 定义 Open Compute Router（OCR）协议的**总体架构与核心设计理念**。OCR 是一套轻量级、可演进的分布式算力路由协议，旨在解决 AI 算力需求爆炸与能源转型瓶颈交织背景下的**电力墙、安全墙、信任墙**三重约束。

## 2. 设计目标

- **中立**：不绑定任何芯片厂商、云厂商或 AI 框架。
- **安全**：基于零信任架构，支持私有算力隔离与端到端加密。
- **算电协同**：将计算任务与电力价格、绿电供给动态匹配，实现"算力跟着电力走"。
- **时效分级**：从 1 分钟实时底座到 24 小时离线批处理，用时间换取成本与能源的最优解。

## 3. 三层架构

```text
[用户层 / AI Agent]
       │  绑定 MCP，声明算力意图（显存、延迟、成本、安全、时效）
       ▼
[Hub 层 / 控制平面]
       │  验证身份，解析意图，匹配能源策略，下发调度指令
       ▼
[Server 层 / 执行平面]
       │  执行计算任务，上报状态，本地对接电网开放数据
       ▼
[算力与电力资源池]  (GPU/NPU/微电网/储能)
```

### 3.1 用户层（User Layer）

AI Agent 通过 MCP 绑定声明算力意图（Compute Intent），包括：显存需求、延迟容忍度、成本上限、安全级别、时效分级。用户层不感知底层算力位置，只声明需求。

### 3.2 Hub 层（控制平面）

作为协议中枢，负责：

- 验证身份（mTLS/SPIFFE）
- 解析算力意图
- 匹配能源策略（电价、绿电比例）
- 下发调度指令
- 维护任务生命周期与审计日志

### 3.3 Server 层（执行平面）

算力提供方，负责：

- 执行计算任务
- 上报实时状态（利用率、能耗、温度）
- 本地对接电网开放数据（AEMO、PJM、ENTSO-E 等）
- 响应抢占与断点续传

## 4. 核心概念

| 概念 | 说明 |
|------|------|
| Compute Intent | 用户声明的算力需求（见 spec/compute-intent.schema.json） |
| SLA Tier | 时效分级（T0-T10，见 RFC-002） |
| Security Level | 安全隔离级别（见 RFC-003） |
| Energy Plugin | 电网数据插件（见 RFC-004） |
| Resource Table | 设备级资源表：每台设备独立维护、类似路由表的「算力 × 能源」视图（见 RFC-005） |

## 6. 演进原则

- **协议先行，代码渐进**：先以 RFC 固化设计，再实现参考代码。
- **向后兼容**：新版本协议不得破坏已有任务声明格式。
- **开放演进**：任何贡献者均可提交 RFC 提案（见 CONTRIBUTING.md）。
