# OCR 商用与企业版策略

> **创建日期**: 2026-09-11
> **状态**: 草案
> **核心原则**: 协议开源中立，商业层做增值服务。不靠"使用费"赚钱，靠"帮客户落地"赚钱。

---

## 1. 开源协议

- **协议层**（RFC 文档、spec、核心参考实现）：**Apache License 2.0**
- **理由**: 最大化采用率，鼓励厂商集成，不设商业门槛
- **不变更承诺**: 协议层永久保持 OSI 认证的开源协议，不搞"开源核心+商业协议"的把戏

---

## 2. 开源版 vs 企业版

### 2.1 功能边界

| 功能 | 开源版 | 企业版 |
|------|--------|--------|
| 协议实现（节点通信、资源表、扩散） | ✅ | ✅ |
| 基础 Hub（任务提交、调度、状态查询） | ✅ | ✅ |
| AEMO 电价接入 | ✅ | ✅ |
| 基础调度（SLA 策略组、电价感知） | ✅ | ✅ |
| Manifest 第一层验证（签名/版本/哈希） | ✅ | ✅ |
| **多租户管理** | ❌ | ✅ |
| **租户优先级与配额** | ❌ | ✅ |
| **Manifest 第二层验证（环境健康声明）** | ❌ | ✅ |
| **DLP 自动检测与脱敏管道** | ❌ | ✅ |
| **审计日志与合规报告** | ❌ | ✅ |
| **SLA 面板与告警** | ✅ 基础 | ✅ 完整 |
| **ComAp/储能适配器** | ❌ 社区版 | ✅ 官方支持 |
| **技术支持** | 社区 | 商业 SLA |
| **高可用部署（多 Hub 集群）** | ❌ | ✅ |

### 2.2 设计原则

- **开源版能跑通完整闭环**：个人用户和小团队用开源版就能完成"提交任务→调度→执行"全流程，不搞"开源版残废"
- **企业版解决"企业才有的问题"**：多租户、合规、审计、高可用——这些是个人用户不需要的
- **协议层不接受企业私有需求**：客户提的协议修改需求，必须经过公开评审，不能为单个客户改协议

## 3. 商标与认证

### 3.1 商标

- "Open Compute Router"、"OCR" 名称和 Logo 为项目方所有
- 开源用户可以用"基于 OCR 协议开发"来描述自己的产品
- 不能用"OCR 官方"、"OCR 认证"等字样，除非获得授权
- 目的：防止劣质产品打着 OCR 旗号损害社区声誉

### 3.2 硬件认证（远期）

- 对通过兼容性测试的硬件（储能控制器、算力节点等）授予"OCR Compatible"标识
- 认证收费：覆盖测试成本 + 小额年费
- 认证标准公开，测试流程透明

## 4. 商业合作模式

### 4.1 集成服务（当前主要收入来源）

- 帮客户把 OCR 集成到现有系统（如 ComAp EMS、PCS 控制器）
- 按项目收费，一次性 + 年度维护
- 典型客户：储能集成商、数据中心运营商、工商业储能业主

### 4.2 企业版 Hub 授权

- 按节点数或按 CPU 核心数授权
- 年度订阅，含版本升级和技术支持
- 适合：有内部 IT 团队、想自己运维的中大型企业

### 4.3 托管服务（远期）

- SaaS 化的 Hub 服务，客户不用自己部署
- 按任务量/算力使用量计费
- 适合：小团队、不想运维的用户

### 4.4 不做的事

- 不做算力交易抽成（保持协议中立，不做"既当裁判又当运动员"）
- 不卖用户数据
- 不强制客户开源自己的业务代码

## 5. 贡献者政策

### 5.1 CLA（贡献者许可协议）

- **当前阶段**: 不强制 CLA，代码版权归贡献者，按 Apache 2.0 授权给项目
- **触发条件**: 当出现以下情况时引入 CLA：
  - 有企业员工开始贡献代码
  - 项目有被收购或融资计划
  - 需要双授权或改变协议的可能性
- **CLA 内容**: 贡献者授予项目方永久的版权许可，保留自己的版权（不要求转让）

### 5.2 企业贡献

- 鼓励企业员工贡献代码
- 企业贡献的功能如果是通用能力，合并进开源版
- 企业贡献的私有功能，放在企业版或客户分支，不进主干

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| 大厂 fork 后自己做，不贡献 | 保持协议迭代速度，让 fork 跟不上；建立社区治理，让大厂有动力参与而不是对抗 |
| 企业版功能被开源社区复刻 | 企业版核心是"服务"和"合规"，不是代码；代码被复刻了，客户还是要找你做集成和支持 |
| 协议被客户私有修改导致碎片化 | 商标控制：只有兼容官方协议的才能叫"OCR Compatible" |
| 早期收入不足 | 阶段一/二不追求收入，先把技术和案例做出来；阶段三有 PoC 后再谈商业 |
