# RFC-012: 算力×电力联合出清与设施物理模型（Twin-Market Clearing & Facility Physical Model）

- **状态**: Draft
- **作者**: Open Compute Router Contributors
- **创建日期**: 2026-10-26
- **最后更新**: 2026-10-26
- **依赖**: RFC-002（时效分级）、RFC-004（能源接入）、RFC-005（设备级自治）、RFC-007（能力上报）、RFC-008（撮合出清）、RFC-003（零信任/IT-OT 边界）

## 1. 摘要与动机

RFC-008 将"任务→资源"升级为**双边撮合**，但撮合只覆盖算力侧（intent × capability），电力侧被当作外部输入的电价信号。算电协同要真正落地，缺两个前提：

1. **算力侧必须有可调度性**——它不只是"用哪张卡"，而是带爬坡、热、PUE 约束的柔性负荷（像储能一样有自己的爬坡能力声明）；
2. **电力侧必须是可对敲的"自有资产集合"**——储能、光伏、电网导入上限，而不只是一条电价曲线。

本 RFC 把 RFC-008 的撮合扩展为**算力 × 电力 × 设施物理的联合出清**（Twin-Market Clearing），定义三层平面划分、双子市场对敲、设施物理模型声明（physical_profile）、防振荡机制与 IT/OT 边界。

## 2. 三层平面划分（架构澄清）

把"算力协同"拆成三个可分离的平面，避免把路由与结算混为一谈：

| 平面 | 形态 | OCR 职责 |
|---|---|---|
| ① 算力调度/路由平面 | **分布式**，设备级自治资源表 | 路由决策去中心化（RFC-005/008），**不做计费** |
| ② 结算/计量平面 | **中心化**，用量回传结算中心 | 提供"计量数据回传接口"，**不去中心化记账** |
| ③ 算电协同平面 | 算力预测 ↔ 电力市场数据 | 本 RFC 核心；可协议内嵌，或机房直连市场（运营方选择） |

**结算平面的先例（电信）**：路由（BGP/OSPF）分布式，结算（计量回传）中心化，两者并存数十年——路由器只做分布式转发决策，用量数据回传 ISP 结算中心。算力同理：**怎么调度、怎么路由是分布式的；用量/计量回传结算中心是中心化的**。因此"无第三方"应精确为**"无第三方控制路由决策"**，而非"无任何中心化记账"（RFC-005 措辞需以此对齐）。

## 3. 双子市场对敲（联合出清）

### 3.1 两个同构市场

| | 算力市场 | 电力市场（自有资产集合） |
|---|---|---|
| 需求侧 | 任务意图（容量/时限/SLA Tier/预算） | 电价曲线（市场数据，RFC-004） |
| 供给侧 | 能力曲线（RFC-007：容量/时隙、最低价、绿电、信任） | 光伏可发、储能可放（SOC）、电网导入上限 |
| 变量 | 量（每时隙+爬坡）· 算力价 · 优先级 | 量（每时隙）· 电价 · 优先级 |

### 3.2 公共交割时隙轴

两个市场必须在**同一个时隙网格**上出清；算力任务的时限（deadline）映射为电力时隙的交付窗口。无公共时间轴，两边各自出清对不上。

### 3.3 耦合约束（把两套市场钉在一起的梁）

```
每时隙算力 × 单位功率(unit_power_kw) ≤ 电网导入 + 储能放电(SOC 约束) + 光伏可发
```

这是"同构"里**唯一的不对称**：电力侧多一层物理约束（MW 上限、爬坡、储能 SOC、接线容量），算力侧没有。**该约束必须进出清问题**，否则"对敲"出的是不可行解。

### 3.4 量、价、优先级精修

- **量**：必须是"每时隙的量"＋爬坡限速；没有时隙轴不可出清，没有爬坡跨时隙过冲。
- **价**：双侧价——电力侧电价曲线、算力侧出清价；对敲再产出一个统一的**影子价格**（稀缺定价）。
- **优先级**：对应 SLA Tier，但按"Tier × 电价"**联合**决定（高优任务即使在贵电时段也跑、用储能兜底；T8-T10 等负电价）；并区分硬承诺（T0-T2）/软计划（T3-T10）。

### 3.5 联立出清（fixed-point）

算力清与电力清必须**一起解**（fixed-point），不是顺序解。顺序解会出现"算力说要跑、但电力不够/太贵"的不一致。这也是防振荡的数学本质：**峰谷↔负荷是自反方程组，在每次承诺时联立求解平衡点，而不是在实时里迭代追自反信号**。

### 3.6 出清产出

- **排程（schedule）**：给 EMS 执行（含爬坡限速后的算力排程）；
- **影子价格（shadow price）**：同时给算力和电力一个统一价格信号，是收费模式与储能收益分配的基础。

## 4. 设施物理层（physical_profile，用户声明）

### 4.1 职责边界

物理模型**不是 OCR 测算**，而是**用户声明**（RFC-005 设备级自治 + AGENTS.md 诚实性的直接延伸）：

| 角色 | 职责 |
|---|---|
| 协议（OCR/spec） | 定义模型**形式/方程**（PUE 怎么进成本、τ 怎么进爬坡、热储能怎么进储能维度） |
| 运营方（配置工程师） | 填**参数值**（经验公式初估 → 实测修正），未知留 n/a |
| OT 遥测 | 实时状态（SOC/温度/功率/电网导入）**实时读取**，不能靠配置 |

### 4.2 字段（见 [spec/physical-profile.schema.json](../spec/physical-profile.schema.json)）

| 字段 | 含义 | 经验初估起点 |
|---|---|---|
| `pue_nominal` | 额定 PUE（设计值） | 风冷 1.3-1.5 / 冷板液冷 1.1-1.2 / 浸没 1.03-1.1 |
| `pue_load_model` | PUE(负载率) 形式 | `PUE(L)=1+(PUE_nominal-1)/L`，低负载每瓦 IT 更贵 |
| `cooling_tau_min` | 冷却热时间常数 | 风冷 10-20 / 冷板液冷 5-15；起点 10 |
| `thermal_storage_kwh` | 热储能（第二种储能） | 蓄冷水罐 E≈7×V_m³×ΔT_K |
| `ramp_limit_pct_per_min` | 电爬坡上限 | 变压器/断路器/UPS 决定，典型 5-15%/min |
| `ramp_limit_thermal_kw_per_min` | 热爬坡上限 | 受 τ 与冷却余量约束；**与电爬坡取小** |
| `power_envelope_kw` | 供电包络 | min(合同/变压器/断路器) − 非计算负载预留 |
| `unit_power_kw` | 单位算力功率 | 耦合约束用 |

### 4.3 经验公式初估 + 人在环校准（三段闭环）

1. **部署**：配置工程师按上表经验公式初估（`source: estimate`，标置信度，别当精确值）；
2. **运行**：OCR 采集**校准遥测**（实测 PUE、冷却滞后、爬坡事件、SOC 曲线）——只提供"该改什么、改多少"的依据，不替用户改；
3. **修正**：用户/工程师按实测修正（`source: calibrated`），记入 `calibration_history` → RFC-007 重新广播能力。

**诚实约束**：未知字段留 `null`/`n/a`，不编造；`source` 必须如实标 estimate/calibrated。

## 5. 防振荡（自反闭环抑制）

自反（reflexivity）：算力响应峰谷 → 峰谷被响应改变 → 信号自指。振荡**不被消除，被界定与抑制**：

1. **死区 + 迟滞 + 随机抖动**：只在电价 < −门槛切入、> 另一个门槛′退出，留一条带；节点间随机错峰 → 打掉同步过冲（bang-bang）；
2. **爬坡限速 / 响应容量上限**：每个时步只翻转柔性车队的 x%，响应是有界斜坡非阶跃；
3. **固定周期重承诺 + 低通滤波 + 环增益 < 1**：只在固定周期（对齐市场 dispatch interval）重排程，不连续追实时价；回传预测做移动平均；闭环增益压到 <1（时延×增益→振荡）；
4. **联立求解固定点**：见 §3.5，预测已含自身响应，而非追逐自反实时信号；
5. **NEM 5 分钟 dispatch interval** = 天然 commit 间隔（承诺间隔）：每个 5 分钟 dispatch interval 开始时提交并锁定"电价门槛 + 响应量"，窗口内价格已出清固定 → 窗口内无自反；跨窗口滞后由市场天然阻尼吸收。

> **价格界限（对标 AEMO 国家标准，AER/AEMC）**：死区门槛与机房价地板必须在市场价格界限内——价格下限 **MFP = -$1,000/MWh**、价格上限 **MPC = $20,300/MWh**（2025-07-01 起）。须区分两个概念：
> - **市场地板价（MFP = -$1,000）**：监管硬下限，电价不可低于此；
> - **机房愿受价（price_floor，RFC-007 业务选择）**：机房愿接受的结算价下限，**必须在 [MFP, MPC] 内**。如 price_floor=-40 意为"愿接任何 ≥ -40 的单"，是合法业务选择。
> 死区阈值（ENTER/EXIT）与机房报价越界时，接入层拒绝，防止把业务报价误当市场标准。

## 6. IT/OT 边界（红线不变）

物理量（冷却功率、温度、PUE）在 **OT 侧**（BMS/EMS/冷却控制），OCR 跑在管理平面（IT 侧）。OCR **不直接控制冷却/储能 PCS**，只做两件事：

- **读**：设施遥测 → 联合出清的**决策输入**；
- **下发**：算力排程（已含爬坡和冷却约束）→ EMS/冷却系统配合执行。

对齐 RFC-003"信息流双向、控制流单向、永不直接控 OT 侧"；物理模型是决策输入，不是执行端。

## 7. 双向数据同步（算电协同平面）

- **接入用电数据**，回传**算力预测 + 用电量预测**给电力市场（需求响应/削峰填谷），使算力节点成为电网柔性可调资源；
- **内部对敲 vs 外部电力市场交互的分界**：OCR 内部能对敲的电力侧**只有自有资产能力集**（储能可放、光伏可发、电网可导 × 电价曲线）。**超出该能力集的部分必须与外部电力市场交互**，需要资质、注册、计量表——这是"协议内嵌"与"机房直连市场"两条路径由谁强制分界的关键。

## 8. 结算钩子（平面②）

联合出清产出**排程 + 影子价格** → 计量回传结算中心（对接 RFC-011）。本 RFC **不定义去中心化结算**；OCR 提供计量回传接口，结算中心化由既有结算基础设施（电力市场结算 / 结算中心 / 国家一体化算力网）承担。

## 9. 与现有 RFC 的关系

- **RFC-008**：本 RFC 是其"算力×电力×设施物理"扩展——RFC-008 保留算力侧双边撮合，联合出清维度见本 RFC §3-6；
- **RFC-004**：补 physical_profile 声明块（§4）与双向数据同步边界（§7）；
- **RFC-007**：能力上报携带 physical_profile（用户声明的物理能力随能力广播）;
- **RFC-005**：设备级自治的物理参数来源——运营方声明、设备本地维护，不依赖第三方测算；
- **RFC-003**：IT/OT 控制边界在 §6 强化；"无第三方"精确化为"无第三方控制路由决策"（§2）。
